## 2025-04-10 - Safely testing modules with broken dependencies
**Learning:** When attempting to add tests to modules with severely broken internal dependencies or missing required third-party libraries (where modifying the source code is prohibited or undesirable), the safest and most effective method is to use a specific local fixture that mocks those dependencies in `sys.modules` via `unittest.mock.patch.dict` and temporarily modifies `sys.path` within a `try/finally` block. This prevents test suite pollution and isolates the hack strictly to the necessary test scope.
**Action:** Implemented a robust `mock_dependencies` fixture for testing `demo_basic_circuits` that intercepts failed module imports before they happen, allowing the core testing logic to execute and verify side-effects like chained method calls cleanly without mutating production code.
